# ADR-0069: A pipeline that consumes model output is verified against model output

## Status

**Accepted** (2026-09-06). States the gap that let
[ADR-0068](0068-a-steps-structure-is-read-from-the-design-not-inferred-from-its-types.md)'s three
defects ship inside a change that was measured end to end and reported green.

## Context

[ADR-0066](0066-generate-renders-the-job-wiring-and-the-stopgap-retires.md) closed G31 with a real
measurement: a project `generate` wired by itself compiles, runs the job to `COMPLETED`, and matches
the transaction oracle across all 50 records and 597 of 600 account fields.
`docs/qa/verification/16-a-generated-project-that-runs.md` records it, and none of it is wrong.

Every number in it was measured against **the fixture design** — `computeInterest`,
`TranCatBalWithRate`, `TranWithContext`: three steps this repository wrote, in
`tests/support/interest_design.py`. Its own bean signature says so:

```java
ItemReader<...TranCatBalWithRate> computeInterestItemReader(
        @Value("${cobol.file.tcatbalf}") Path tcatbalf, ...)
```

**No design a live `solution_architect` produced had ever reached `render_job_wiring`.** The next run
that pointed it at one refused, and behind that refusal were three defects — none of them reachable
from the fixture, because the fixture declares no `computed_fields`, no `tasklet` and no `reader`
step, and every one of its steps takes a composite rather than a plain entity. That last one hid a
fourth: `render_item_reader`'s return expression read `new TranCatBal(toTranCatBal(record))`, a
record handed to its own four-argument constructor.

Four defects, one shared property: **the fixture cannot express the input that triggers them.** It is
not a weak fixture. It is a fixture, and a fixture is written by the same people who write the code,
so it encodes the same assumptions about what a design looks like. A renderer whose input is
*generated by a model* has an input space nobody in this repository chose.

This is the same argument ADR-0030 made for parsing over asking a model, pointed at the test suite
instead of at the renderer: a wrong assumption produces plausible output, and only a differential
against something you did not author catches it.

## Decision

**A design a model produced is pinned as a fixture, and the wiring is held to it.**

`tests/fixtures/live_designs/cbact04c-design.json` is the `design.json` from run
`step54b-cbact04c-20260905-211254`, saved verbatim. `tests/integration/test_a_live_design_wires.py`
runs `run_generate` against it with scripted `return null;` processor bodies — enough to compile, and
claiming nothing about generated logic, which keeps this module free of a model call.

Three properties make it worth its Maven build:

1. **It is pinned, not regenerated.** Re-deriving it from a model each run would make the test's
   subject change under it, and the point is that this input is *not* this repository's idea of what
   a design looks like.
2. **It asserts the refusals are gone by name** — no missing driving stream, no ambiguous bean — not
   merely that something rendered.
3. **It pins what still fails to its exact cause.** The project does not compile, because the design
   types two item-carrying steps as `writer` (ADR-0068's Consequences). The test asserts those are
   the *only* errors, so a fifth defect fails it rather than hiding behind a known one. This is the
   discipline `assert_account_half_matches_except_the_last` already applies to the account
   half's three mismatches.

## Consequences

**The claim in verification 16 gains a qualifier rather than losing its numbers.** "A project
`generate` wired by itself builds and runs" remains true and remains measured; what it did not say,
and now says, is *for the design this repository wrote*.

**A second live design is the next thing this needs**, per `CLAUDE.md`'s standing rule that a
capability is complete when a second instance exercises it. One pinned design proves the shapes one
model produced on one program on one day.

**The fixture will go stale, and that is the intended cost.** When the design-time refusal for
`writer`-typed transforms lands, this design becomes one a live run would no longer produce. It stays
anyway: it is the input that found four defects, and a regression suite's job is to keep failing on
inputs that once broke something. The test says in its own docstring what to change when that
happens.

**It costs a Maven build in CI**, on the integration tier, alongside the two round trips already
there.

## Alternatives considered

**Widen the fixture design to carry the shapes that broke.** Cheaper, and it closes exactly the four
holes now known — which is the objection. The next defect will be in a shape nobody added, and the
whole finding here is that this repository cannot enumerate what a model will write.

**Assert on the design at the contract layer instead — refuse the shapes the renderers cannot take.**
Partly right, and ADR-0068 does refuse two of them. But a refusal that fires at design time still
needs something to prove the *renderers* handle what is not refused, and that is a rendered project
or nothing.

**Generate the processor bodies with a real model call so the project also runs.** Rejected: it puts
a model call, a cost and a source of variance into a test whose subject is wiring. The differential
belongs in `test_generate_renders_the_wiring.py`, where it is measured against the oracle.
